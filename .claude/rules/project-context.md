# 2. LA IDEA MÁS IMPORTANTE

Este proyecto NO trata simplemente de enseñar más lenguajes de programación.

Parte de una idea mucho más profunda:

> **Antes de aprender a escribir código, el estudiante necesita aprender a pensar cómo resolver un problema.**

Programar implica desarrollar:

* pensamiento lógico;
* pensamiento abstracto;
* pensamiento computacional;
* análisis;
* resolución estructurada de problemas;
* autonomía;
* capacidad para aprender del error.

La experiencia que se quiere replantear es aquella donde el estudiante simplemente:

**escucha → memoriza → replica código → presenta una evaluación.**

El proyecto imagina una experiencia más cercana a:

**comprender → practicar → resolver → equivocarse → colaborar → mejorar → competir → evolucionar.**

# 4. PROBLEMA QUE MOTIVA LA INVESTIGACIÓN

Las asignaturas relacionadas con Algoritmos y Programación pueden convertirse en una barrera académica importante.

El problema no debe reducirse a:

“los estudiantes pierden programación”.

Existen varias dimensiones.

## Enseñanza tradicional

Parte de la enseñanza puede concentrarse excesivamente en sintaxis, contenidos y explicación magistral.

Pero:

> **Saber escribir código no significa necesariamente saber resolver problemas.**

El modelo quiere fortalecer el razonamiento que existe antes del código.

---

## Poca práctica colaborativa y competitiva

La programación también requiere experiencias donde el estudiante pueda:

* resolver retos;
* trabajar con otros;
* tomar decisiones;
* enfrentarse al error;
* administrar tiempo;
* explicar soluciones;
* trabajar bajo presión controlada.

La competencia dentro del proyecto debe entenderse como:

# COMPETENCIA FORMATIVA

No se trata simplemente de determinar quién gana.

Se utiliza el reto como herramienta para aprender.

---

## Talento que puede pasar desapercibido

Dentro de las aulas pueden existir estudiantes con capacidades importantes para:

* lógica;
* algoritmos;
* resolución de problemas;
* programación competitiva.

El proyecto contempla construir una ruta que en el futuro permita:

**IDENTIFICAR → FORTALECER → CONECTAR → PREPARAR → PROYECTAR**

ese talento.

La visión competitiva puede conducir hacia escenarios como:

* retos internos;
* hackatones;
* maratones de programación;
* programación competitiva;
* ICPC y competencias relacionadas.

Esto representa una **visión de progresión**, no una estructura que deba presentarse como actualmente implementada.

# 5. LOS TRES PILARES

## REFUERZO

Idea:

> **No todos comienzan desde el mismo punto. Todos deberían tener una ruta para avanzar.**

Refuerzo significa:

* fortalecer fundamentos;
* detectar dificultades;
* practicar;
* acompañar;
* ofrecer retroalimentación;
* desarrollar progresivamente la lógica.

Frase corta recomendada:

# REFUERZA

Fortalece tus bases.

---

## PARTICIPACIÓN COMPETITIVA

Idea:

Los problemas pueden transformarse en desafíos que motiven al estudiante a aplicar lo aprendido.

Involucra:

* retos;
* equipos;
* gamificación;
* programación competitiva;
* colaboración;
* resolución bajo presión;
* hackatones;
* maratones.

Frase corta recomendada:

# COMPITE

Convierte problemas en desafíos.

La competencia debe sentirse exigente pero positiva.

Nunca hostil.

---

## RETENCIÓN / PERMANENCIA

Existe una posible cadena negativa:

**Dificultad → Frustración → Reprobación → Retraso → Desmotivación → Riesgo de deserción**

El proyecto busca favorecer otra trayectoria:

**Refuerzo → Comprensión → Progreso → Motivación → Permanencia**

Frase corta recomendada:

# AVANZA

Transforma progreso en permanencia.

IMPORTANTE:

La investigación todavía no ha demostrado que reduzca la deserción.

Hablar siempre de:

* fortalecer la permanencia;
* contribuir;
* prevenir;
* disminuir factores asociados;
* buscar mejores condiciones para avanzar.

# 6. POSTURA DEL PROYECTO FRENTE A LA IA

Este punto debe comunicarse con mucho cuidado.

El proyecto **NO está en contra de la Inteligencia Artificial**.

La IA es una herramienta poderosa para:

* desarrollar;
* optimizar;
* investigar;
* acelerar tareas;
* construir sistemas complejos.

El problema aparece cuando sustituye prematuramente el proceso cognitivo de un estudiante que todavía está construyendo sus fundamentos.

La diferencia conceptual es:

## Dependencia prematura

**Problema → IA → Código**

versus:

## Desarrollo lógico

**Problema → Análisis → Abstracción → Algoritmo → Solución → Código → IA como potenciador**

Frase principal recomendada:

# La IA puede escribir código.

# Pero primero tú debes aprender a pensar.

Alternativa:

> **Primero desarrolla tu lógica. Después poténciala con IA.**

Nunca comunicar:

* “la IA es mala”;
* “no uses IA”;
* “programar con IA es hacer trampa”.

La postura correcta es:

> **La IA debe potenciar el razonamiento, no reemplazar su construcción.**

# 15. PRINCIPIO DE CREDIBILIDAD

Nunca convertir una aspiración en un resultado.

NO afirmar:

* “redujimos la deserción”;
* “mejoramos las notas”;
* “transformamos la enseñanza”;
* “tenemos un laboratorio”;
* “tenemos equipos ICPC”;
* “el modelo ya funciona”;
* “los estudiantes mejoraron X%”.

Utilizar:

* buscamos;
* proponemos;
* estamos diseñando;
* se espera;
* podría contribuir;
* está orientado a;
* la investigación plantea;
* la visión contempla.
